# API

Python 3.15 + FastAPI on uv, everything under `api/src/`. A generic `core/` engine of 34 domains carries every integration; a Laravel-shaped application sits on it as thin pipelines; `bootstrap/` is the only opinionated glue. Gate: `uv run ruff check`, `uv run mypy`, `uv run pytest`, `uv run python -m bootstrap check`.

## Layout

```
api/
├── src/
│   ├── core/       41 domains, one folder of flat files (100–300 lines, a law) each, a facade __init__ with __all__ and a lowercase singleton
│   ├── app/        enums  utils/{dna,cycle}  models  repositories  services  controllers  middlewares
│   │               requests  resources  mails  jobs  events  listeners  exceptions      (every folder a plural lowercase package)
│   ├── config/     one core Settings class per group: app auth broadcast(+socket) cache database docs event log mail queue(+schedule) storage(+assets); llm is plain LLM_* parameters
│   ├── routes/     api/ (the heartbeat and the routes without the version prefix)  channel/ (broadcast channels)  events/ (listeners map)  schedule/ (tasks)
│   ├── database/   migrations/NNNN_name.py (the schema DSL, no SQL)  seeders/
│   ├── views/      layouts/ mail/  (Jinja, async)
│   ├── public/     project assets: robots.txt, images/brand/…  (served under ASSETS_URL with content stamps)
│   ├── storage/    app/{public,private}  logs   (public served under STORAGE_URL, private only through routes; relocatable by STORAGE_*)
│   ├── bootstrap/  app.py (Application: configs, routing, wiring)  boot.py (the lifespan)  cli.py (commands over core/cli)  serve.py  __main__.py
│   └── tests/      business tests (Laravel style): test_{application,auth,files,cycle,repositories}.py, no pytest import, run through the root conftest
```

## Layer chain and laws

```
core → app/enums → config → app/utils/dna → app/utils/cycle → models → repositories → services
     → controllers · middlewares · mails · jobs · events · listeners · exceptions → requests · resources → routes
```

glued by `bootstrap/`; `database/` is data the core runs; `views/` are templates the core renders.

- **Import law** (a test): `core` imports only `core`; `config`, `app`, `database` and `routes` import only `core` and `app`; `bootstrap` imports everything but `tests`; `src/tests` may import every part; above the core nothing imports a third-party library or a stdlib module beyond `collections typing enum dataclasses contextlib` (pydantic, starlette, fastapi, functools, sys … all live behind core verbs); `tests/` and `benches/` import only the core (the bench base alone boots `bootstrap`); the core domains form a DAG checked by AST.
- **Shadow law** (a test): a class that defines a verb named like a builtin type (`env.bool`, `parse.list`, `storage.list`, `rand.float`) annotates that type as `builtins.<name>` everywhere in its body; a bare name there would resolve to the verb at runtime (annotation scopes) and break `get_type_hints`, which mypy never sees.
- **Typing law** (a test): outside `core`, no file imports `datetime uuid pathlib decimal json orjson asyncio os re hashlib base64 secrets random time`. The unified types come from the core: `core.date.DateTime/TimeDelta/UTC`, `core.rand.Uuid`, `core.fs.Path`, `core.number.Decimal`, `core.json.JsonValue`; `collections.abc`, `typing`, `enum` and `dataclasses` stay allowed. A leaf that needs a regex, a hash or a clock asks the core for a verb.
- **Core laws**: final wrapper (every third-party library and every network, file, process access lives in `core`; no third-party type crosses its facade); generic engine (no business logic, product name, model or migration); async-only I/O, pure CPU helpers sync, CPU-heavy work offloaded through `thread.offload`; one domain = one folder of flat files of 100–300 lines (a test refuses a longer or a nested file) + a facade; unified errors (`Fault`); logs for everything; domains depend downward only; `log` is the floor (it serializes with orjson itself so `json → error → log` has no cycle); no `core/base`.
- **Outbox law**: a side effect that must survive the request (a queued job, a remote event, a broadcast frame) never waits in memory for a commit: `queue.durable(outbox)`, `events.durable(outbox)` and `broadcast.durable(outbox)` write it in the same transaction, so a rollback erases it, a commit delivers it, and a crash between the two only delays it until the relay (running in every process with workers) picks it up. Delivery is at least once; consumers rely on the job or event id. A deliverer returns only once the side effect is accepted downstream and raises otherwise: a durable broadcast awaits the Redis `PUBLISH` (`driver.deliver`, `UNAVAILABLE broadcast.redis`, `unknown` on a timeout) before framing locally, so an outage keeps the row and the relay sends it later; the fire-and-forget `emit` is the best-effort path.
- **Adapter law**: every provider is a `core.adapter.Adapter` with a `family`, a `name` and declared `capabilities`; an unsupported capability or option is an explicit `Fault` before any I/O, never a silent skip, a fake success or a `None`; a missing setting fails at construction (`<family>.<name>.config.<field>`); HTTP providers subclass `core.net.Remote`, which maps `401/403 → .key`, `404`, `409`, `429 → .rate` with `retry_after`, other `4xx → .request` with the provider message, the rest `unavailable`, for plain calls and SSE streams alike; registries are `Manager[A]`. Fault reasons are fixed codes: no path, key, id, pointer, archive member, date text or other input ever goes into a reason the client can see (`fs.missing`, `fs.path`, `json.patch.path`, `date.parse`, `archive.member`, `lock.busy`, `net.port`, `throttle`); only an `INTERNAL` fault may name a developer identifier (a rule, a model, a template).
- **Gravity in practice**: a controller is one or two lines over a service; a service is a thin pipeline over repositories and core verbs; a repository is a `Query` chain; a model is behaviorally empty (frozen dataclass + relations + tiny predicates); enums carry the vocabulary and the behavior on their cases; a mail, a job, a listener and an event are declarations over their base classes. When any of these needs more, the "more" is a new verb in a core domain, with a test in `test_core.py` or `test_database.py`.

Migrations: one table per file, no SQL, every index named and created `IF NOT EXISTS`, partial uniques for soft-deleted identities, an index on every foreign key:

```python
class Migration:

    async def up ( self, schema: Schema ) -> None:

        def define ( table: Blueprint ) -> None:

            table.id()
            table.string("name", 120)
            table.string("email", 254)
            table.string("password", 255).nullable()
            table.timestamps()
            table.soft_deletes()
            table.unique(["lower(email)"], name="users_email_alive", where="deleted_at IS NULL")
            table.index("created_at")

        await schema.create(Table.USERS, define)

    async def down ( self, schema: Schema ) -> None:
        await schema.drop(Table.USERS)
```

Blueprint verbs: `id uuid string char text binary integer big_integer small_integer boolean float decimal json array inet interval date time timestamp timestamps soft_deletes enum foreign morphs index unique gin brin fulltext primary check comment drop_column drop_timestamps drop_soft_deletes drop_morphs rename_column drop_index drop_unique drop_check drop_primary drop_foreign rename_index`, columns chain `.nullable .default .unique .index .key .comment .generated .references`; `Schema`: `create create_if_missing table drop drop_all rename comment has has_column has_index columns tables indexes constraints size truncate`.

Query, generative and immutable: filters `where where_not where_in where_not_in where_null where_not_null where_like where_not_like where_between where_not_between where_date where_all where_either where_column where_raw where_key where_keys order_by order_by_desc latest oldest in_random_order reorder limit offset take skip for_page select distinct with_ without with_trashed only_trashed lock_for_update shared_lock when unless tap clone within to_sql dump`; readers `get first first_or_fail sole find find_or_fail find_many count exists missing sum avg min max value pluck(column, key) paginate chunk cursor each`; writers `create insert upsert(items, conflict, update) update touch first_or_create update_or_create increment decrement delete destroy force_delete restore truncate`; string binds untyped so PostgreSQL infers enum, uuid and text; reads on autocommit connections, multi-statement writes in `transaction()`.

## Envelope and protocol

- Every answer: `data message errors code reason meta.request_id` plus `meta.{page,limit,total,pages}` when paginated; headers `X-Request-Id`, `X-RateLimit-*`, `X-Content-Type-Options: nosniff`; `Authorization: Bearer`.
- `GET /health` reports `status version release database{status alive ready driver size idle busy overflow} checks{database cache queue events storage llm} ms` from `core/health` and degrades to `503 unavailable` without the pool; `release` is `APP_RELEASE` (the image tag in production).
- Socket frames `{event, channel?, data?, id?}` with system events `connected subscribed unsubscribed member_joined member_left pong error`.
- Throttling keys on `Request.ip()`: `X-Forwarded-For` counts only through `APP_PROXIES` (private ranges by default), walking from the peer back to the first untrusted hop, so a client that spoofs hops still lands in its own bucket; a `429` carries `Retry-After` and the reason `throttle`.
- Verified edge contract: the production edge (haproxy `set-header X-Forwarded-For %[src]`, lab nginx `$remote_addr`) overwrites the header with the real client and reaches the api from a docker bridge address inside the default `APP_PROXIES`, so `Request.ip()` is the real client and spoofed hops never count.
- Edge lab (2026-10-19, nginx 1.24 `proxy_set_header X-Forwarded-For $remote_addr` in front of the current api, clients bound to distinct loopback addresses): client A's 21st login in a minute is `429` with `Retry-After: 58`; a spoofed `X-Forwarded-For` or a spoofed chain through the edge stays in A's bucket; client B keeps its own bucket. The boundary it also shows: a peer inside `APP_PROXIES` is believed, so a direct caller from a trusted range picks its own bucket. The api must be reachable only from the edge, and production narrows `APP_PROXIES` to the edge's network.
- Paymob wire (verified 2026-10-19 against Paymob's official Postman collection): refund `POST /api/acceptance/void_refund/refund`, void `…/void_refund/void`, capture `POST /api/acceptance/capture`, all with `Authorization: Token <secret_key>` and a numeric `transaction_id` (+ `amount_cents`); transaction inquiry `GET /api/acceptance/transactions/{id}` needs a Bearer token from `POST /api/auth/tokens` with the `api_key` (cached 50 minutes); intention `POST /v1/intention/` with the secret key.
- Provider wires verified 2026-10-19 against the official specs (`test_contracts.py`) and stripe-mock: Twilio sends media as a repeated `MediaUrl` form field; a WhatsApp template language carries `policy: deterministic` beside its `code`; Vercel DNS records list at `/v5/domains/{zone}/records` and `companyName` is sent only when set; PayTabs drops empty optional fields (`return`, `customer_details`) instead of sending `null`; Stripe reads a null session currency or amount from the request and sends `application/x-www-form-urlencoded` on bodiless POSTs (void, cancel).
- Auth: login always pays one argon2 verify (a cached decoy hash when the email is unknown), so timing never tells which emails exist; a refresh token rotates inside one transaction and only when its conditional revoke wins, so a raced refresh yields one session and `token.revoked` for the rest (a test fills the pool with `database.fill` to make the race real); forged, `alg:none`, truncated and payload-swapped access tokens are all `401 token`.

## Bootstrap and commands

- `Application()` loads the env and registers configs on demand; `create()` = `log.setup → wire → http.build(routing, docs, lifespan) → http.serve(assets) → http.serve(storage public) → /robots.txt → the websocket route`; `wire()` installs the exception handler, token, crypto, assets, view globals, mail transport, storage disks, the cache store, the queue driver, the event bus and subscriptions, auth ttls, socket limits, the broadcasting guard and driver (`local|redis`) and the llm providers (every provider with a key, `local` always), each chosen by its `config/*` driver key.
- `Boot.lifespan`: (connect → migrate/seed → `database.fill(DB_POOL_MIN)`) ‖ warm the OpenAPI ‖ primers (bootstrap passes app warmers such as the login decoy hash) → warm `/health` and `{prefix}/hello` → `queue.start(workers)` → `events.start()` (remote consumer, only in processes with workers) → `broadcast.start()` → `schedule.start(tick)`; shutdown: schedule → sockets → broadcast → events → queue → llm → cache → database, each graceful (idle queue workers leave at once, in-flight jobs finish within the wait). Measured 2026-10-19: boot ready 45 ms median in process (pool min 1), shutdown 1.5–4 ms (was 504 ms); `DB_POOL_MIN=8` cuts the slowest of eight first requests from 74 ms to 25–39 ms for +35–65 ms of boot, so the default is 4.
- `python -m bootstrap [serve | check | runbook | work | schedule | migrate | rollback [steps] [--force] | status | seed]` through `core/cli` (`bootstrap/cli.py`, default `serve`, `help` lists the groups server/workers/database). `work` runs the queue workers and the event consumer without the scheduler; `schedule` runs the scheduler without workers; `check` boots the full lifespan and exits; `rollback` in production needs `--force` (exit 1 `rollback.force` otherwise); `runbook` prints routes, channels, schedule, queues, handlers, commands, the event, cache and llm descriptions, the redacted config and the operation count as JSON.

## Configuration

One `core.config.Settings` class per group in `config/` (`class XConfig(Settings, env_prefix="X_")`, `field(default, env=…, ge=…)`, `hidden` names kept out of `describe()` and the runbook), no pydantic import: `app auth broadcast cache database docs event log mail queue storage`. Folded groups keep their env names through aliases: `SOCKET_*` live in `broadcast` (`socket path connections outbox frame ping drops`), `SCHEDULE_ENABLED/TICK` in `queue` (`schedule tick`), `ASSETS_*` in `storage` (`assets assets_url assets_cache versioned`). The llm is plain parameters read in `bootstrap` (`LLM_DRIVER LLM_TIMEOUT LLM_RETRIES LLM_SESSION_TTL` and one `LLM_<PROVIDER>_{KEY,MODEL,URL}` triple; an unset model or url falls back to the provider default). Every key is documented in `api/.env.example`; a key nobody reads is removed (`SCHEDULE_TIMEZONE` was). Drivers are keys: `QUEUE_DRIVER=memory|sync|rabbitmq`, `EVENT_DRIVER=local|rabbitmq`, `CACHE_DRIVER=memory|redis`, `MAIL_DRIVER=log|mailgun` (+ `MAIL_MAILGUN_{KEY,DOMAIN,REGION}`), `STORAGE_DISK=public|s3`, `BROADCAST_DRIVER=local|redis`, `LLM_DRIVER=local|chatgpt|claude|gemini|deepseek`; `APP_PROXIES` lists the trusted proxy ranges. A new knob is a field with a default, a line in `.env.example`, and a test when it changes behavior.

## Tests

- Flat, brutal, few, and all written in the `core/test` DSL (no bare `assert`, no `pytest.raises`; third-party imports in `tests/` and `benches/` are `pytest` alone, plus `jsonschema` and `yaml` inside `test_contracts.py`, pinned by the law `TOOLS`/`PROOFS`): `expect(value)` verbs, `test.fails(code, reason, field)` / `test.rejects(awaitable, …)` / `test.raises(kind)` naming the exact `Fault`, `test.some(x)` and `test.kind(x, T)` that narrow, `test.client(app, base, peer, lifespan)` → `Answer` (`status ok created fault(code, reason, field) header lacks data(path) expect(path) cookie text json`), `test.sockets(app)` → `connect(path)` peers (`send text receive frames closed`) and `refused(path)`, `test.stub()` as the in-memory websocket, `net.mocked(fn)` for every remote wire. Against the real `ragx_test` database booted through the real lifespan (`conftest.py` sets `APP_ENV=testing MAIL_DRIVER=log QUEUE_DRIVER=memory QUEUE_WORKERS=0 SCHEDULE_ENABLED=false DB_MIGRATE=true DB_SEED=true`); the broker tests drive the real local RabbitMQ and Redis; provider tests speak the exact wire formats through `net.mocked`, never the network.
- `test_live.py` is the opt-in proof against real providers: each test skips unless its `LIVE_*` keys are set (`LIVE_STRIPE_TEST_KEY`, `LIVE_STRIPE_MOCK_URL`, `LIVE_PAYPAL_CLIENT_ID/SECRET`, `LIVE_PAYMOB_SECRET_KEY/PUBLIC_KEY/INTEGRATION` (+ `LIVE_PAYMOB_REGION`), `LIVE_PAYTABS_SERVER_KEY/PROFILE_ID` (+ `LIVE_PAYTABS_REGION/CURRENCY`), `LIVE_MAILGUN_KEY/DOMAIN/TO`, `LIVE_CLOUDFLARE_TOKEN/ACCOUNT`) and refuses anything but a Stripe `sk_test_` key, the PayPal sandbox, a Paymob `_sk_test_` key, a PayTabs hosted page (no money moves until a customer pays), a Mailgun `sandbox` domain or read-only registrar calls; every test closes its manager in `finally`.
- `test_contracts.py` is the opt-in proof against the providers' own contracts: with `CONTRACT_SPECS` pointing at a folder of the official specs (`paypal_{checkout_orders_v2,payments_payment_v2,payments_payouts_batch_v1,notifications_webhooks_v1}.json` from paypal/paypal-rest-api-specifications, `openai.json`, `twilio.json` (twilio_api_v2010), `vercel.json`, `cloudflare.json`, `whatsapp.yaml` (Meta's business-messaging spec), `gemini.json` (the Generative Language discovery document)), it records every request the adapters send through `net.mocked` and validates method, path, unknown fields and the JSON Schema of each body (discriminator variants resolved, `allOf` flattened); zero findings is the pass. `LIVE_STRIPE_MOCK_URL` runs every Stripe verb against stripe-mock, which validates against Stripe's OpenAPI. A test that opens a provider closes its manager in `finally`.
- Opt-in proofs on real servers (each skips without its env): `test_llm` live runs `local` over any OpenAI-compatible server (`LLM_LIVE_URL/MODEL`: complete with usage and finish, stream, models, JSON mode, an attached text, a four-message session through `Llm`, the explicit refusals of metadata and documents) and images over a vision model (`LLM_LIVE_VISION_URL/MODEL`: a red and a blue PNG must be named); `test_storage` runs the storage contract on a real S3 bucket (`S3_TEST_ENDPOINT/KEY/SECRET/BUCKET`, optional `S3_TEST_REGION`): put, text, size, modified, files and directories, append, copy, move, stream, delete twice, an upload, a presigned GET answered 200 with the bytes, and the failure paths (missing, `..` keys, refused credentials, missing bucket). Verified 2026-10-19 with llama.cpp build 11723 serving Qwen2.5-0.5B-Instruct Q4_K_M and SmolVLM-256M-Instruct Q8_0 (hashes checked against Hugging Face) and RustFS.
- `test_laws.py` is the constitution: the hand style (one blank line, a blank line after every def, zero comments, the `__main__` shape), core files flat and 100–300 lines (a module under 100 lines merges into its cohesive sibling, one over 300 sheds a mixin; facades and empty packages are exempt), the import direction and the core DAG, core raising only `Fault`, every core facade exporting only names the core or the stdlib defines (an `Annotated` alias counts when its metadata is core), every public verb defined in core speaking no library type in its signature (read through `annotationlib` FORWARDREF; the one declared raw surface is `core.database` speaking `sqlalchemy` in `execute fetch row value where_raw dialect connection` and the schema builders; engine plumbing is private `_name_` or a module function, `Transport` is an opaque core value, the socket endpoint is a property), migrations speaking only the DSL, every core domain exporting a facade and the root importing every domain. A new domain or layer registers itself there.
- A test asserts exact values and the failure path (`422` with the field, `401` with the code, a `Fault` with the reason, a `429` after the limit, a rejected upload, a tampered token, a cross-tenant read refused). A test that mocks something runnable, or that passes without exercising code, is removed.
- Performance budgets live in the benches, not in the tests.

## Benches

`benches/__init__.py` provides `Bench` (`quiet`, `budget(label, fallback)` from `BENCH_<LABEL>_P99_MS` × `BENCH_SCALE`, `client()` = `test.client` over the real lifespan, `boot()` = one create → ready → shutdown cycle, `measure(work, rounds, concurrency)` in wall time, `measure_sync(work, rounds, clock)` in CPU time (`thread_time` by default, `process_time` for native multi-threaded work such as argon2) so another process on the machine cannot fail a micro budget, `settle`/`asettle` re-measure a breached case up to `BENCH_REPEATS` (3) times and report the run that was kept, `within` for single spans). Each flat `bench_<name>.py` is a law: it prints throughput and percentiles and exits non-zero on any unexpected status or a blown budget. `bench_micro` covers uuid7 otp parse slug base64 email `shape.of` `json.encode/decode` `envelope` `query.build` `query.sql` (render, not a hot path) `route.url` `cron.next` `frame.decode` jwt seal argon2 and the queue/event/cache pipeline; `bench_hello`, `bench_auth` drive HTTP through the real lifespan; `bench_socket` the fan-out; `bench_boot` the boot cycle (create, ready, shutdown) and the first burst of eight concurrent requests right after boot. Benches run on demand (`uv run python -m benches.bench_hello`), never in CI; their numbers go into the report and, when measured on a quiet machine, into `README.md`.

## How to add

- **A core verb or domain**: create the flat file(s) (≤ 300 lines each, a mixin or a helper class per concern) and the facade, register the module in `core/__init__.py`, keep the DAG downward, pin it in `test_core.py`, `test_lifecycle.py` or its own flat file, document it in the table above. No product words inside.
- **A lifecycle feature**: enum → migration (DSL) → model → repository → service → controller → request/resource → route → test (`test_http.py` or its own flat file) → bench when hot. Each layer stays one or two lines; the moment a layer needs more, go back to the core.
- **A job, event, listener, mail or task**: a class over its base, declared in `routes/{events,schedule}` or dispatched from a service; `Queued` decides queued vs inline; a test drains the memory queue by hand.
- **A config knob**: a field with a default, `.env.example`, the wiring branch in `bootstrap/app.py`, a test when it changes behavior, the infra template `compose/api.env` when production must set it.
- **A provider** (llm, mail, sms, storage, broker, gateway, domain): an `Adapter` subclass in its domain with declared `capabilities`, registered on the domain's `Manager`, chosen by a driver key; a log/memory/sandbox implementation for tests and the real one proven against the real service or its exact wire format through `net.mocked`; an HTTP provider subclasses `core.net.Remote` (an llm one `Provider`, or `Compatible` for an OpenAI-shaped api) and maps only its wire format (`body answer chunks usage_of` for llm); every capability it lacks has a failing test naming the Fault.

## Production contract

The infra renders the api env from its own knobs: `APP_HOST=0.0.0.0 APP_PORT=8000 APP_RELEASE=<tag> APP_URL APP_ORIGINS`, `DB_*` to the `postgres` service, `QUEUE_URL`/`EVENT_URL` to `rabbitmq`, `CACHE_URL` to `redis`, `LOG_RENDERER=json`, `STORAGE_*`, `AUTH_SECRET`, `DOCS_ENABLED`; the http process runs `QUEUE_WORKERS=0` and `SCHEDULE_ENABLED=false` when a worker and a scheduler service exist.
