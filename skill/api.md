# API

Python 3.15 + FastAPI on uv, everything under `api/src/`. A generic `core/` engine of 42 domains carries every integration; an empty, law-checked Laravel-shaped application waits on it for the product; `bootstrap/` is the only opinionated glue. Gate: `uv run ruff check`, `uv run mypy`, `uv run pytest`, `uv run python -m bootstrap check`.

## Layout

```
api/
├── src/
│   ├── core/       42 domains, one folder of flat files (100–300 lines, a law) each, a facade __init__ with __all__ and a lowercase singleton
│   ├── app/        enums(mode)  utils/{dna(identity, timestamps),cycle}  models  repositories  services  controllers  middlewares
│   │               requests  resources  mails  jobs  events  listeners  exceptions      (every folder a plural lowercase package)
│   ├── config/     one core Settings class per group: app auth broadcast(+socket) cache database docs event llm log mail queue(+schedule) storage(+assets)
│   ├── routes/     api/ (the product routes without the version prefix, empty)  channel/ (broadcast channels)  events/ (listeners map)  schedule/ (tasks)
│   ├── database/   migrations/NNNN_name.py (the schema DSL, no SQL; the framework ships 0001_create_outbox)  seeders/ (an empty tuple)
```

## Layer chain and laws

```
core → app/enums → config → app/utils/dna → app/utils/cycle → models → repositories → services
     → controllers · middlewares · mails · jobs · events · listeners · exceptions → requests · resources → routes
```

glued by `bootstrap/`; `database/` is data the core runs; `views/` are templates the core renders.

- **Import law** (a test): `core` imports only `core`; `config`, `app`, `database` and `routes` import only `core` and `app`; `bootstrap` imports everything but `tests`; `src/tests` may import every part; above the core nothing imports a third-party library or a stdlib module beyond `collections typing enum dataclasses contextlib` (pydantic, starlette, fastapi, functools, sys … all live behind core verbs); `tests/` and `benches/` import only the core (the bench base alone boots `bootstrap`); the core domains form a DAG checked by AST.
- **Shadow law** (a test): a class that defines a verb named like a builtin type (`env.bool`, `parse.list`, `storage.list`, `rand.float`) annotates that type as `builtins.<name>` everywhere in its body; a bare name there would resolve to the verb at runtime (annotation scopes) and break `get_type_hints`, which mypy never sees.
- **Typing law** (a test): outside `core`, no file imports `datetime uuid pathlib decimal json orjson asyncio os re hashlib base64 secrets random time`. The unified types come from the core: `core.date.DateTime/TimeDelta/UTC`, `core.rand.Uuid`, `core.fs.Path`, `core.number.Decimal`, `core.json.JsonValue`; `collections.abc`, `typing`, `enum` and `dataclasses` stay allowed. A leaf that needs a regex, a hash or a clock asks the core for a verb.
- **Core laws**: final wrapper (every third-party library and every network, file, process access lives in `core`; no third-party type crosses its facade); generic engine (no business logic, product name, model or migration); async-only I/O, pure CPU helpers sync, CPU-heavy work offloaded through `thread.offload`; one domain = one folder of flat files of 100–300 lines (a test refuses a longer or a nested file) + a facade; unified errors (`Fault`); logs for everything; domains depend downward only; `log` is the floor (it serializes with orjson itself so `json → error → log` has no cycle); no `core/base`.
- **Outbox law**: a side effect that must survive the request (a queued job, a remote event, a broadcast frame) never waits in memory for a commit: `queue.durable(outbox)`, `events.durable(outbox)` and `broadcast.durable(outbox)` write it in the same transaction, so a rollback erases it, a commit delivers it, and a crash between the two only delays it until the relay (running in every process with workers) picks it up. Delivery is at least once; consumers rely on the job or event id. A deliverer returns only once the side effect is accepted downstream and raises otherwise: a durable broadcast awaits the Redis `PUBLISH` (`driver.deliver`, `UNAVAILABLE broadcast.redis`, `unknown` on a timeout) before framing locally, so an outage keeps the row and the relay sends it later; the fire-and-forget `emit` is the best-effort path.
- **Adapter law**: every provider is a `core.adapter.Adapter` with a `family`, a `name` and declared `capabilities`; an unsupported capability or option is an explicit `Fault` before any I/O, never a silent skip, a fake success or a `None`; a missing setting fails at construction (`<family>.<name>.config.<field>`); HTTP providers subclass `core.net.Remote`, which maps `401/403 → .key`, `404`, `409`, `429 → .rate` with `retry_after`, other `4xx → .request` with the provider message, the rest `unavailable`, for plain calls and SSE streams alike; registries are `Manager[A]`. Fault reasons are fixed codes: no path, key, id, pointer, archive member, date text or other input ever goes into a reason the client can see (`fs.missing`, `fs.path`, `json.patch.path`, `date.parse`, `archive.member`, `lock.busy`, `net.port`, `throttle`); only an `INTERNAL` fault may name a developer identifier (a rule, a model, a template). A provider answers `abilities()`: its class capabilities unless the model family or an explicit `serves=` declaration says otherwise; `supports`, `require`, `describe` and the manager matrix read only that.
- **Turn law**: a conversation turn is saved only after a validated success (non-empty, schema-valid), inside a per-session lane, with a compare-and-set save when sessions are durable; a stream yields provisional chunks under a shrinking per-chunk deadline (never a `yield` inside a cancel scope) and one terminal `done` after persistence; an incomplete stream or a timeout is an unknown outcome (`llm.stream.incomplete`, `llm.timeout`) and saves nothing.
- **Schema law**: native structured output is used only where the provider declares `schema`; each provider receives the projection it can enforce and the full `Schema` is always validated locally; `schema(shape, native=False)` is the explicit instruction mode.
- **Retrieval law**: a scope is an application-derived namespace, never an authorization check; one embedding identity per scope; documents are replaced whole and atomically after all their embeddings exist; context sources are untrusted data with control markers stripped; a citation must name a supplied source.
- **Model law**: the llm layer knows no model name and no local/remote split: one `Model` value (`model url key name driver tasks serves headers timeout retries window options`) builds any driver (`chatgpt claude gemini deepseek local`, `llm.DRIVERS`), and only the adapter knows its far side. Work is routed by task (`generate summarize evaluate embed rank ocr describe transcribe`, `llm.NEEDS` lists the capabilities each needs): a model declares its tasks, boot refuses a model that cannot serve one (`llm.<name>.task.<task>`), `llm.task(name)` answers the first declarer unless `LLM_TASKS__<TASK>` picks another, and a missing task is `llm.task.<task>.missing`. Options are one vocabulary for every provider (`temperature top_p top_k stop seed presence frequency effort` + `max_tokens json schema metadata extra`): a feature the model lacks (`json schema metadata` or an attachment kind) is a `Fault` before any I/O, a tuning knob or effort level it lacks is dropped and logged (`llm.options.ignored`; `describe` lists `tunes` and `efforts`), and `extra` merges raw fields into the body. Effort maps to `reasoning_effort` (OpenAI wire, all seven levels), `output_config.effort` (Claude: `low medium high xhigh max`) and `thinkingConfig.thinkingLevel` (Gemini: `minimal low medium high`). Compaction runs on the `summarize` model when one is registered. Local models are served by infra; the api only reads their address.
- **Extraction law**: every file is read by code first and by a model only where code cannot. `core.fs.Extraction` parses in a fresh `python -I` worker (`reader.py` for documents, `media.py` for images, audio and video) under address-space, CPU, file-size and core-dump rlimits, with libraries loaded lazily per format, so a hostile file can kill only its worker. A PDF page is read by pdfium, re-read by pypdf when its Arabic looks reversed or garbled (`reader.legible`: words starting with a final-only letter, Latin-extended letters glued to Arabic, replacement or private-use characters), and left as an `ocr` gap otherwise; presentation forms are folded. What code cannot read comes back as typed `Gap`s (`ocr` with a page, `vision`, `speech` and `frames` with a time span), never as invented text, and `core.rag` fills them with the `ocr`, `describe` and `transcribe` models (a dedicated transcription endpoint, else an audio-capable chat model under a schema). Archives are refused here (`file.archive`); `fs.archive` owns them.
- **Recovery law** (tests on real systems, `tests/test_recovery.py`): a pooled Postgres connection idle longer than `IDLE` (5 s) is pinged at checkout and replaced when dead (a blanket `pre_ping` measured +5–8 ms p50 on hello and is refused); a Redis outage makes `get`, `set` and `lock` raise `UNAVAILABLE cache` (locks fail closed) while `hit` degrades to a process-local counter and counts `shed`; RabbitMQ rides a robust connection: publishing while it is down is `UNAVAILABLE broker.rabbitmq`, consumers resume by themselves, an ack or reject on a dead channel is the same `Fault` and the message comes back redelivered (at least once, so handlers are idempotent); queue workers supervise `Fault` only (transient → `queue.worker.stalled` with a backoff up to 5 s, any other fault logged with its trace) and a non-`Fault` is a bug that ends the worker visibly. `core.test` carries `Relay(host, port)` to cut, sever and restore a real service mid-operation.
- **Tenancy law**: row-level security is the second wall. `blueprint.isolated(column="tenant_id", setting="app.tenant")` enables and forces RLS with one fail-closed policy (`column = NULLIF(current_setting(setting, true), '')::<column type>`, USING and WITH CHECK, so the index still serves it); `Schema.isolate/share/isolated` do the same on a live table. Settings bind per transaction through `set_config(name, value, true)`: explicitly with `with database.bound({...})`, or from a context slot with `database.follow(setting, slot)` so a request, the jobs it dispatches and the events it raises carry the tenant by themselves; a bound read opens a transaction, binding inside an open transaction is refused (`database.bound.open`), and a policy violation is `FORBIDDEN database.privilege`. The runtime role never bypasses RLS: `python -m bootstrap provision` (core `Cluster`) creates it `NOSUPERUSER NOBYPASSRLS`, gives it its own database with PUBLIC revoked and installs `DB_EXTENSIONS` as the admin (`DB_ADMIN_*`); boot warns `database.bypasses_isolation` otherwise.
- **Egress law**: every URL a user supplies is fetched through `core.net.Egress` (schemes, hosts, ports, every resolved address public, the connection pinned to the checked address with the original Host and SNI, each redirect checked again, no environment proxies); `storage.fetch` uses it by default.
- **Stream law**: an SSE response drains its source in one producer task into a bounded queue; keep-alive pings wait on the queue and never cancel the source; a `Fault` from the source becomes one `error` event with its code and reason. A grounded answer streams through `Rag.stream` (chunks, then one `Answer` whose citations are the `[S#]` labels the text names) and `Builder.ground(sources)` sends the sources for that turn only, so a durable session stores the question, never the sources.
- **Isolation law**: importing `bootstrap` has no side effect (`application` is a factory), so the test environment wins over `.env`, and the shared fixture refuses a database that is not the test one; the in-process test client runs every request in its own task, so a context slot set by one request never leaks into the test or the next request. `python -m bootstrap check` boots the full lifespan twice and compares `test.footprint()` (every container held by every core singleton, plus live tasks): a registry that grows is `check.leaked` naming it.
- **Gravity in practice**: a controller is one or two lines over a service; a service is a thin pipeline over repositories and core verbs; a repository is a `Query` chain; a model is behaviorally empty (frozen dataclass + relations + tiny predicates); enums carry the vocabulary and the behavior on their cases; a mail, a job, a listener and an event are declarations over their base classes. When any of these needs more, the "more" is a new verb in a core domain, with a test in `test_core.py` or `test_database.py`.

## DSLs

Routes (`routes/api/__init__.py`, empty in the framework), wrapped by the bootstrap in `Route.group(APP_PREFIX)` so names compose as `v1.orders.show`; `/health` is the bootstrap's own route. A product adds its routes like:

```python

        Route.get("/{key}", orders.show, name="show").constrained(key="uuid"),
```

Migrations: one table per file, no SQL, every index named and created `IF NOT EXISTS`, partial uniques for soft-deleted identities, an index on every foreign key, `isolated()` on every tenant table:

```python
class Migration:

    async def up ( self, schema: Schema ) -> None:
```

## Envelope and protocol

- Every answer: `data message errors code reason meta.request_id` plus `meta.{page,limit,total,pages}` when paginated; headers `X-Request-Id`, `X-RateLimit-*`, `X-Content-Type-Options: nosniff`; `Authorization: Bearer`.
- `GET /health` reports `status version release database{status alive ready driver size idle busy overflow} checks{database cache queue events storage llm} ms` from `core/health` and degrades to `503 unavailable` without the pool; `release` is `APP_RELEASE` (the image tag in production).
- Socket frames `{event, channel?, data?, id?}` with system events `connected subscribed unsubscribed member_joined member_left pong error`.
- Throttling keys on `Request.ip()`: `X-Forwarded-For` counts only through `APP_PROXIES` (private ranges by default), walking from the peer back to the first untrusted hop, so a client that spoofs hops still lands in its own bucket; a `429` carries `Retry-After` and the reason `throttle`.
- Verified edge contract: the production edge (haproxy `set-header X-Forwarded-For %[src]`, lab nginx `$remote_addr`) overwrites the header with the real client and reaches the api from a docker bridge address inside the default `APP_PROXIES`, so `Request.ip()` is the real client and spoofed hops never count.
- Edge lab (2026-10-19, nginx 1.24 `proxy_set_header X-Forwarded-For $remote_addr` in front of the current api, clients bound to distinct loopback addresses): client A's 21st login in a minute is `429` with `Retry-After: 58`; a spoofed `X-Forwarded-For` or a spoofed chain through the edge stays in A's bucket; client B keeps its own bucket. The boundary it also shows: a peer inside `APP_PROXIES` is believed, so a direct caller from a trusted range picks its own bucket. The api must be reachable only from the edge, and production narrows `APP_PROXIES` to the edge's network.
- Paymob wire (verified 2026-10-19 against Paymob's official Postman collection): refund `POST /api/acceptance/void_refund/refund`, void `…/void_refund/void`, capture `POST /api/acceptance/capture`, all with `Authorization: Token <secret_key>` and a numeric `transaction_id` (+ `amount_cents`); transaction inquiry `GET /api/acceptance/transactions/{id}` needs a Bearer token from `POST /api/auth/tokens` with the `api_key` (cached 50 minutes); intention `POST /v1/intention/` with the secret key.
- Provider wires verified 2026-10-19 against the official specs (`test_contracts.py`) and stripe-mock: Twilio sends media as a repeated `MediaUrl` form field; a WhatsApp template language carries `policy: deterministic` beside its `code`; Vercel DNS records list at `/v5/domains/{zone}/records` and `companyName` is sent only when set; PayTabs drops empty optional fields (`return`, `customer_details`) instead of sending `null`; Stripe reads a null session currency or amount from the request and sends `application/x-www-form-urlencoded` on bodiless POSTs (void, cancel).

## Bootstrap and commands

- `bootstrap.application()` is the factory (importing `bootstrap` loads nothing); `Application()` loads the env and registers configs on demand; `create()` = `log.setup → wire → http.build(routing, docs, lifespan) → http.serve(assets) → http.serve(storage public) → /robots.txt → the websocket route`; `wire()` installs the exception handler, token, crypto, assets, view globals, mail transport, storage disks, the cache store, the queue driver, the event bus and subscriptions, socket limits, the broadcasting driver (`local|redis`, no guard until a product sets one), the llm models (`LlmConfig.models()`: every endpoint with a `model` and a `url` or `key`, routed by task, with the global window, compaction and timeout) and the framework health checks (`bootstrap/health.py`: database, cache, queue, events, storage, llm), each chosen by its `config/*` driver key.
- `Boot.lifespan`: (connect → migrate/seed → `database.fill(DB_POOL_MIN)`) ‖ warm the OpenAPI ‖ primers (none in the framework; a product passes its warmers) → warm `/health` → `queue.start(workers)` → `events.start()` (remote consumer, only in processes with workers) → `broadcast.start()` → `schedule.start(tick)`; shutdown: schedule → sockets → broadcast → events → queue → llm → cache → database, each graceful (idle queue workers leave at once, in-flight jobs finish within the wait). Measured 2026-10-19: boot ready 45 ms median in process (pool min 1), shutdown 1.5–4 ms (was 504 ms); `DB_POOL_MIN=8` cuts the slowest of eight first requests from 74 ms to 25–39 ms for +35–65 ms of boot, so the default is 4.
- `python -m bootstrap [serve | check | runbook | work | schedule | provision | migrate | rollback [steps] [--force] | status | seed]` through `core/cli` (`bootstrap/cli.py`, default `serve`, `help` lists the groups server/workers/database). `work` runs the queue workers and the event consumer without the scheduler; `schedule` runs the scheduler without workers; `check` boots the full lifespan twice and fails on any leaked registry or task; `provision` creates the runtime role, its database and the extensions as the admin (`DB_ADMIN_USERNAME/PASSWORD/DATABASE`, `DB_EXTENSIONS`), idempotently; `rollback` in production needs `--force` (exit 1 `rollback.force` otherwise); `runbook` prints routes, channels, schedule, queues, handlers, commands, the event, cache and llm descriptions, the redacted config and the operation count as JSON.

## Configuration

One `core.config.Settings` class per group in `config/` (`class XConfig(Settings, env_prefix="X_")`, `field(default, env=…, ge=…)`, `hidden` names kept out of `describe()` and the runbook), no pydantic import: `app auth broadcast cache database docs event log mail queue storage`. Folded groups keep their env names through aliases: `SOCKET_*` live in `broadcast` (`socket path connections outbox frame ping drops`), `SCHEDULE_ENABLED/TICK` in `queue` (`schedule tick`), `ASSETS_*` in `storage` (`assets assets_url assets_cache versioned`). `llm` (`LlmConfig`, `nested_model_default_partial_update`) holds `default session_ttl timeout window compact keep tasks` and one `Endpoint` field per model (`writer summarizer embedder ranker vision listener` local, `chatgpt claude gemini deepseek` remote) with `driver model url key tasks serves headers timeout retries window defaults`; an env key fills one field and keeps the rest (`LLM_WRITER__URL`, `LLM_CLAUDE__KEY`, `LLM_TASKS__GENERATE=claude`, JSON for lists), `key` stays out of `describe()` through the nested `hidden`, and a remote model name is always explicit, never a stale default. Every key is documented in `api/.env.example`; a key nobody reads is removed (`SCHEDULE_TIMEZONE` was). Drivers are keys: `QUEUE_DRIVER=memory|sync|rabbitmq`, `EVENT_DRIVER=local|rabbitmq`, `CACHE_DRIVER=memory|redis`, `MAIL_DRIVER=log|mailgun` (+ `MAIL_MAILGUN_{KEY,DOMAIN,REGION}`), `STORAGE_DISK=public|s3`, `BROADCAST_DRIVER=local|redis`, `APP_PROXIES` lists the trusted proxy ranges; `DB_ADMIN_{USERNAME,PASSWORD,DATABASE}` and `DB_EXTENSIONS` serve only `provision`. A new knob is a field with a default, a line in `.env.example`, and a test when it changes behavior.

## Tests

- Flat, brutal, few, and all written in the `core/test` DSL (no bare `assert`, no `pytest.raises`; third-party imports in `tests/` and `benches/` are `pytest` alone, plus `jsonschema` and `yaml` inside `test_contracts.py`, pinned by the law `TOOLS`/`PROOFS`): `expect(value)` verbs, `test.fails(code, reason, field)` / `test.rejects(awaitable, …)` / `test.raises(kind)` naming the exact `Fault`, `test.some(x)` and `test.kind(x, T)` that narrow, `test.client(app, base, peer, lifespan)` → `Answer` (`status ok created fault(code, reason, field) header lacks data(path) expect(path) cookie text json`), `test.sockets(app)` → `connect(path)` peers (`send text receive frames closed`) and `refused(path)`, `test.stub()` as the in-memory websocket, `net.mocked(fn)` for every remote wire, and `sample` building real files from the stdlib (`pdf scanned docx xlsx zipped wav png`). Against the real `ragx_test` database booted through the real lifespan (`conftest.py` sets `APP_ENV=testing MAIL_DRIVER=log QUEUE_DRIVER=memory QUEUE_WORKERS=0 SCHEDULE_ENABLED=false DB_MIGRATE=true DB_SEED=true`); the broker tests drive the real local RabbitMQ and Redis; provider tests speak the exact wire formats through `net.mocked`, never the network.
- `test_live.py` is the opt-in proof against real providers: each test skips unless its `LIVE_*` keys are set (`LIVE_STRIPE_TEST_KEY`, `LIVE_STRIPE_MOCK_URL`, `LIVE_PAYPAL_CLIENT_ID/SECRET`, `LIVE_PAYMOB_SECRET_KEY/PUBLIC_KEY/INTEGRATION` (+ `LIVE_PAYMOB_REGION`), `LIVE_PAYTABS_SERVER_KEY/PROFILE_ID` (+ `LIVE_PAYTABS_REGION/CURRENCY`), `LIVE_MAILGUN_KEY/DOMAIN/TO`, `LIVE_CLOUDFLARE_TOKEN/ACCOUNT`) and refuses anything but a Stripe `sk_test_` key, the PayPal sandbox, a Paymob `_sk_test_` key, a PayTabs hosted page (no money moves until a customer pays), a Mailgun `sandbox` domain or read-only registrar calls; every test closes its manager in `finally`.
- `test_contracts.py` is the opt-in proof against the providers' own contracts: with `CONTRACT_SPECS` pointing at a folder of the official specs (`paypal_{checkout_orders_v2,payments_payment_v2,payments_payouts_batch_v1,notifications_webhooks_v1}.json` from paypal/paypal-rest-api-specifications, `openai.json`, `twilio.json` (twilio_api_v2010), `vercel.json`, `cloudflare.json`, `whatsapp.yaml` (Meta's business-messaging spec), `gemini.json` (the Generative Language discovery document)), it records every request the adapters send through `net.mocked` and validates method, path, unknown fields and the JSON Schema of each body (discriminator variants resolved, `allOf` flattened); zero findings is the pass. `LIVE_STRIPE_MOCK_URL` runs every Stripe verb against stripe-mock, which validates against Stripe's OpenAPI. A test that opens a provider closes its manager in `finally`.
- Opt-in proofs on real servers (each skips without its env): `test_llm` live runs `local` over any OpenAI-compatible server (`LLM_LIVE_URL/MODEL`: complete with usage and finish, stream, models, JSON mode, an attached text, a four-message session through `Llm`, the explicit refusals of metadata and documents) and images over a vision model (`LLM_LIVE_VISION_URL/MODEL`: a red and a blue PNG must be named); `test_storage` runs the storage contract on a real S3 bucket (`S3_TEST_ENDPOINT/KEY/SECRET/BUCKET`, optional `S3_TEST_REGION`): put, text, size, modified, files and directories, append, copy, move, stream, delete twice, an upload, a presigned GET answered 200 with the bytes, and the failure paths (missing, `..` keys, refused credentials, missing bucket). Verified 2026-10-19 with llama.cpp build 11723 serving Qwen2.5-0.5B-Instruct Q4_K_M and SmolVLM-256M-Instruct Q8_0 (hashes checked against Hugging Face) and RustFS.
- AI and retrieval: `test_ai.py` pins policies, immutable prompts, native/local/projected schemas, turn commit semantics, stream terminals and partials, per-session serialization, timeouts as unknown, durable sessions on Postgres with lost-update refusal, compaction, and strict embedding/rerank parsing; `test_llm.py` pins every wire, model specs and task routing, the tuning vocabulary on each wire (effort levels kept or dropped), compaction on the summarizer and multipart transcription; `test_retrieval.py` pins vectors, folding, chunks, safety, schemas, search and extraction on real files (PDFs, a scanned page, Word, Excel, HTML, mail, CP1256 text, WAV with tags, a subtitled MP4 built by ffmpeg when present, symlinks, FIFOs, root escapes, archives, a starved worker) plus the Arabic legibility gate and `Reader` filling OCR, vision, speech and frame gaps through mocked models; `test_rag.py` runs one index contract against `MemoryIndex` and `PostgresIndex` (the Postgres variant skips only while the test database lacks the `vector` extension) plus grounding, context, rerank, judge, uploads, summaries in rounds, fused rewrites and per-call providers; `TestLive` runs the whole stack on real servers when `RAG_LIVE_{GENERATION,EMBEDDING,RANKING}_{URL,MODEL}` are set (verified 2026-10-19 with llama.cpp b11723 serving Qwen3.5-2B Q4_K_M, Qwen3-Embedding-0.6B Q8_0 and bge-reranker-v2-m3 Q8_0, over MemoryIndex and pgvector 0.8.7 on PostgreSQL 18.6: English and Arabic questions retrieve the refund policy first, the answer cites it and states 14 days).
- Small apps instead of a product: `test_application` pins the bare framework (`/health`, docs, assets, nothing else), `test_orm` runs the relations, morphs, soft deletes, typed faults and the whole query DSL on scratch models, `test_journey` crosses every real system in one flow (an outbox row, a RabbitMQ worker that carries the scope through `database.follow`, an RLS-isolated pgvector index, a Redis broadcast, an SSE grounded answer with citations), and `src/tests/test_cycle` pins the cycle bases with local declarations.
- `test_laws.py` is the constitution: the hand style (one blank line, a blank line after every def, zero comments, the `__main__` shape), core files flat and 100–300 lines (a module under 100 lines merges into its cohesive sibling, one over 300 sheds a mixin; facades and empty packages are exempt), the import direction and the core DAG, core raising only `Fault`, every core facade exporting only names the core or the stdlib defines (an `Annotated` alias counts when its metadata is core), every public verb defined in core speaking no library type in its signature (read through `annotationlib` FORWARDREF; the one declared raw surface is `core.database` speaking `sqlalchemy` in `execute fetch row value where_raw dialect connection` and the schema builders; engine plumbing is private `_name_` or a module function, `Transport` is an opaque core value, the socket endpoint is a property), migrations speaking only the DSL, every core domain exporting a facade and the root importing every domain. A new domain or layer registers itself there.
- A test asserts exact values and the failure path (`422` with the field, `401` with the code, a `Fault` with the reason, a `429` after the limit, a rejected upload, a tampered token, a cross-tenant read refused). A test that mocks something runnable, or that passes without exercising code, is removed.
- Performance budgets live in the benches, not in the tests.

## Benches

`benches/__init__.py` provides `Bench` (`quiet`, `budget(label, fallback)` from `BENCH_<LABEL>_P99_MS` × `BENCH_SCALE`, `client()` = `test.client` over the real lifespan, `boot()` = one create → ready → shutdown cycle, `measure(work, rounds, concurrency)` in wall time, `measure_sync(work, rounds, clock)` in CPU time (`thread_time` by default, `process_time` for native multi-threaded work such as argon2) so another process on the machine cannot fail a micro budget, `settle`/`asettle` re-measure a breached case up to `BENCH_REPEATS` (3) times and report the run that was kept, `within` for single spans). Each flat `bench_<name>.py` is a law: it prints throughput and percentiles and exits non-zero on any unexpected status or a blown budget. `bench_micro` covers uuid7 otp parse slug base64 email `shape.of` `json.encode/decode` `envelope` `query.build` `query.sql` (render, not a hot path) `route.url` `cron.next` `frame.decode` jwt seal argon2 and the queue/event/cache pipeline; `bench_hello` and `bench_auth` are small apps mounted on the framework through `Bench.client(*routes)` over the real lifespan (hello: shape validation and one PostgreSQL lookup; auth: argon2 login, JWT `me` with one row, refresh rotation in one transaction, on scratch tables, behind the same throttles); `bench_models` measures a live model stack when `RAG_LIVE_*` are set (embedding, rerank, exact token count, a 32-token answer); `bench_extract` the sandboxed extraction per file (2026-10-20: text inline p50 0.07 ms; a 20-page PDF 87 ms, Word 106 ms, a 2000-row sheet 104 ms, WAV 109 ms, a 10 s clip 116 ms, a page render 118 ms, all dominated by the worker start); `bench_socket` the fan-out; `bench_boot` the boot cycle (create, ready, shutdown) and the first burst of eight concurrent requests right after boot. `bench_rag` measures the memory index over 1000 × 1024 vectors (dense, lexical, hybrid, chunking) and, when the database has pgvector, `PostgresIndex` ingestion and hybrid search at 1k and 5k rows, asserting the HNSW plan at 5k after `ANALYZE` (2026-10-19 on pgvector 0.8.7: p50 15.0 ms at 1k, 15.7 ms at 5k; before the MAIN storage, bounded lexical pool and one-row identity check the 5k p50 was 100 ms). Benches run on demand (`uv run python -m benches.bench_hello`), never in CI; their numbers go into the report and, when measured on a quiet machine, into `README.md`.

## Lint and types

- ruff 0.17+, `select = ["ALL"]`, 120 columns, `src = ["src","tests","benches"]`; per-file ignores are listed in `pyproject.toml` with their reason in the commit (complexity in the code set, the parse probes, the date formatter and the enums, `S311` in `rand/pick`, `S608` in the seeders, `BLE001` in the exception handler, the thread tasks and signals, the fs watcher, the queue, schedule task and event rabbit runners that must survive a failing job, `T201` in the command entry point and the benches, the test allowances).
- mypy strict with `warn_unreachable` and the pydantic plugin over `src tests benches`. Protocols with properties describe settings so `Literal` fields satisfy `str`; a `Fault` re-raised from itself hides the cause; `FastAPI.openapi` is overridden by subclassing; dataclass fields never shadow a base attribute.

## How to add

- **A core verb or domain**: create the flat file(s) (≤ 300 lines each, a mixin or a helper class per concern) and the facade, register the module in `core/__init__.py`, keep the DAG downward, pin it in `test_core.py`, `test_lifecycle.py` or its own flat file, document it in the table above. No product words inside.
- **A lifecycle feature**: enum → migration (DSL) → model → repository → service → controller → request/resource → route → test (`test_http.py` or its own flat file) → bench when hot. Each layer stays one or two lines; the moment a layer needs more, go back to the core.
- **A job, event, listener, mail or task**: a class over its base, declared in `routes/{events,schedule}` or dispatched from a service; `Queued` decides queued vs inline; a test drains the memory queue by hand.
- **A config knob**: a field with a default, `.env.example`, the wiring branch in `bootstrap/app.py`, a test when it changes behavior, the production env file (`API_ENV_FILE`) when production must set it.
- **A provider** (llm, mail, sms, storage, broker, gateway, domain): an `Adapter` subclass in its domain with declared `capabilities`, registered on the domain's `Manager`, chosen by a driver key; a log/memory/sandbox implementation for tests and the real one proven against the real service or its exact wire format through `net.mocked`; an HTTP provider subclasses `core.net.Remote` (an llm one `Provider` built from a `Model`, or `Compatible` for an OpenAI-shaped api, listed in `llm.DRIVERS`) and maps only its wire format (`body answer chunks usage_of`, plus its `base`, `keyed`, `tunes` and `efforts` for llm); every capability it lacks has a failing test naming the Fault.

## Production contract

The application env is one file the infra receives as `API_ENV_FILE` and mounts read-only as `/app/.env`: `APP_URL APP_ORIGINS`, `DB_*` to the `postgres` service, `QUEUE_URL`/`EVENT_URL` to `rabbitmq`, `CACHE_URL` to `redis`, `LOG_RENDERER=json`, `STORAGE_*`, `AUTH_SECRET`, `DOCS_ENABLED` and the `LLM_*` endpoints. The infra forces only what it owns, as process variables that outrank the file (`API_FORCED_ENV`: `APP_HOST=0.0.0.0 APP_PORT=8000`, the storage root, `DB_MIGRATE=false`; the role variables, so the http process runs `QUEUE_WORKERS=0` and `SCHEDULE_ENABLED=false` when a worker and a scheduler service exist; `APP_RELEASE=<tag>`). The image runs as uid 33 on a read-only root with `/tmp` on tmpfs and `src/storage` on a volume; `python -m bootstrap` is the entrypoint and `serve work schedule migrate status runbook` its verbs. Retrieval needs the `vector` extension (pgvector ≥ 0.8) in the application database, created once by a superuser (the image or an init script; `Schema.extension` only re-asserts it); vector columns use MAIN storage so exact scans stay inline, and HNSW engages once the planner prices it below an exact scan. Local models are infra services (llama.cpp, vLLM or a whisper server pinned by digest, weights mounted read-only); the api reaches them only through `LLM_<MODEL>__URL`, `__MODEL` and `__KEY`.
